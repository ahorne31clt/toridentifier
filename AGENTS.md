# Tornado Guesser release maintenance

- Every user-facing change must be recorded in the site's What’s New / release-notes section in `index.html` and `patchnotes.txt`.
- Group fixes under Bug fixes and new capabilities under Improvements or New features. Describe the behavior players will notice.
- Consolidate related patch notes periodically instead of growing an unstructured list.
- Advance the version appropriately, including patch versions such as 1.8.1. Keep the release heading, footer version, patch notes, README release summary, and changed asset cache keys consistent.
- Preserve existing gameplay, stored scores, accounts, and backend functionality when updating.
- Match official DAT tracks using verified event dates, ratings, geography, and source records. Do not substitute a nearby tornado or invent a historical track.
